# Импорт имитационного бота в Bot-Control

Документ фиксирует, как устроен `bot/imitation_bot.txt` — конфиг демо-бота
**Подработка.МСК** для приложения
[Bot-Control](https://github.com/visiontripin/Bot-Control), и почему он
проходит импорт **без единого замечания**.

- **Файл для импорта:** `bot/imitation_bot.txt`
- **Копия для git:** `bot/imitation_bot.py` (идентична байт-в-байт)
- **Режим работы:** имитация, без базы данных — все смены, отклики и статусы выдуманы

---

## Как импортировать

1. Откройте бота в Bot-Control → **Скрипты → Импорт настроек из кода**.
2. Вставьте содержимое `bot/imitation_bot.txt` (или выберите файл).
3. Нажмите **🔍 Разобрать** — раздел **«Замечания»** должен быть пустым.
4. **✅ Применить к боту** → **▶ Этот бот** → отправьте `/start` в Telegram.

Токен в файле не хранится: `BOT_TOKEN = "НЕ_ИМПОРТИРУЕТСЯ"`, токен задаётся в
настройках импорта Bot-Control.

---

## Главный принцип: импортёр не исполняет код

Bot-Control разбирает конфиг **статически** — он читает текст файла и строит по
нему декларативные правила. Всё, что вычисляется во время выполнения, импортёр
не видит: он не подставляет переменные, не выполняет конкатенацию строк и не
вызывает функции с аргументами, чтобы узнать результат.

Отсюда единственное правило этого конфига: **всё, что должно попасть в бота,
должно быть видно в тексте файла буквально.**

| Написано так | Импортёр видит | Итог |
|---|---|---|
| `callback_data="job:" + str(job_id)` | `"job:"` | ❌ кнопки `job:101` «без обработчика» |
| `callback_data="job:101"` | `"job:101"` | ✅ обработчик найден |
| `call.data.startswith("job:")` | префикс, не значение | ❌ нажатия «не найдены» |
| `call.data == "job:101"` | конкретное значение | ✅ нажатие привязано |
| `job_detail_keyboard(job_id, st)` | функция с аргументами | ❌ меню «не прикреплено» |
| `jobs_menu()` без аргументов | готовая клавиатура | ✅ меню прикреплено |
| текст из `for` + `+` + `.get()` | «вычисляется в коде» | ❌ «перенесён как «…»» |
| строковый литерал | весь текст целиком | ✅ текст перенесён |

## Разобранные замечания (15 → 0)

Первая версия конфига получила 15 замечаний. Причина у всех одна — динамика в
коде. Ниже что именно было не так и как исправлено.

### 1. Пять кнопок смен: «обработчик нажатия не найден»

```
⚠️ Кнопка «🏬 Грузчик на склад Wildberries — 4500 ₽» (callback_data="job:101"):
   обработчик нажатия не найден
```
…и то же для `job:102` … `job:105`.

**Было:** `callback_data="job:" + str(job_id)` — импортёр видел только префикс
`"job:"`, а кнопку регистрировал как `job:101`. Совпадения не было.

**Стало:** пять кнопок с литеральными данными и пять отдельных функций:

```python
def jobs_menu():
    markup = InlineKeyboardMarkup()
    markup.row(InlineKeyboardButton("🏬 Грузчик на склад — 4500 ₽", callback_data="job:101"))
    ...
    return markup

@bot.callback_query_handler(func=lambda call: call.data == "job:101")
def cb_job_101(call):
    ...
```

### 2. Два отклика: «обработчик нажатия не найден»

```
⚠️ Кнопка «Отклик #7 — ⏳ Ожидает решения» (callback_data="myapp:7") …
⚠️ Кнопка «Отклик #5 — ✅ Принят» (callback_data="myapp:5") …
```

**Было:** `"myapp:" + str(app_id)` в цикле по списку откликов.

**Стало:** две кнопки `app:7` и `app:5`, две функции `cb_app_7` / `cb_app_5`.

### 3. `cmd_profile()`: «текст ответа вычисляется в коде — перенесён как «…»»

**Было:** функция `job_text()` собирала карточку смены из словаря:

```python
"💰 " + money(j.get("pay", 0)) + " ₽ за смену\n" + ...
```

Импортёр не может выполнить этот код, поэтому переносил текст как заглушку `«…»`.

**Стало:** все 32 текста ответов — обычные строковые литералы. Карточки смен,
списки, профиль, тарифы, помощь прописаны явным текстом. Проверка: `max` длина
текста — 900 символов при лимите Telegram 4096.

### 4. Пять меню «объявлено, но не прикреплено»

```
⚠️ Меню job_detail_keyboard() объявлено, но не прикреплено …
⚠️ Меню my_jobs_keyboard() объявлено, но не прикреплено …
⚠️ Меню candidates_keyboard() объявлено, но не прикреплено …
⚠️ Меню app_detail_keyboard() объявлено, но не прикреплено …
⚠️ Меню my_job_detail_keyboard() объявлено, но не прикреплено …
```

**Было:** меню-фабрики с аргументами — `job_detail_keyboard(job_id, has_applied)`.
Импортёр ищет привязку в виде `reply_markup=имя()` **без аргументов** и такие
фабрики пропускал, хотя они вызывались из обработчиков.

**Стало:** пять меню без параметров, каждое прикреплено к команде-разделу:

| Меню | Прикреплено | Кнопок |
|---|---|---|
| `jobs_menu()` | `/Найти смену` + карточки смен | 6 / 12 |
| `apply_menu()` | `/Откликнуться` + результат отклика | 5 / 12 |
| `applications_menu()` | `/Мои отклики` | 2 / 12 |
| `my_jobs_menu()` | `/Мои смены` | 2 / 12 |
| `candidates_menu()` | `/Кандидаты` | 4 / 12 |

### 5. Попутно устранено

- **`parse_mode` и HTML.** Убраны все `<b>` / `<i>` — Bot-Control отправляет
  обычный текст без разметки, теги показывались бы пользователю как символы.
- **`import`.** Убран `import telebot` — объект `bot` и классы клавиатур
  инжектит само приложение.
- **f-строки.** Заменены на конкатенацию/литералы.
- **`sessions`, `global`, циклы по данным.** Состояние ролей убрано, логика
  разложена на отдельные команды — меньше вычислений, которые импортёр не видит.
- **`startswith(...)` в callback.** Заменён на точные сравнения `==`.

## Проверка конфига

Конфиг прогнан двумя способами: статическим анализом (как это делает импортёр) и
исполнением в симуляторе среды Bot-Control (подставные `bot`, `ReplyKeyboardMarkup`,
`InlineKeyboardButton`, `BotCommand`).

```
✅ Синтаксис Python                     OK
✅ import / f-строки / parse_mode / HTML  0 вхождений
✅ Reply-кнопки                          11 / 11 → своё правило m.text == "..."
✅ callback_data                         18 / 18 → своя функция с точным ==
✅ Лишние callback-обработчики           0
✅ Inline-меню                           5 / 5 прикреплены, все без аргументов
✅ Тексты ответов                        все литералы, max 900 / 4096
✅ Тосты                                 все ≤ 180 символов
✅ Лимиты меню                           ≤ 12 кнопок, ≤ 8 рядов
✅ Команды Telegram                      /start, /help, /examples
✅ Ошибки выполнения в симуляторе        0
```

> обработчике — то же меню.

## Демо-сценарий для проверки

1. `/start` → приветствие и нижняя клавиатура.
2. **Найти смену** → список из 5 смен + меню под сообщением.
3. Нажать любую смену → карточка откроется в этом же сообщении, меню останется.
4. **Откликнуться** → выбрать смену → «✅ Отклик отправлен». Смена `apply:104`
   (Промоутер) показывает «мест нет» и лист ожидания.
5. **Мои отклики** → `app:7` (ожидает) и `app:5` (принят) с контактами работодателя.
6. **Мои смены** → `myjob:101` активна, `myjob:103` на паузе.
7. **Кандидаты** → принять или отклонить кандидатов #12 и #13.
8. `/examples` → инструкция по каждой кнопке.

Незнакомый текст → бот отвечает одним из `CLARIFY_QUESTIONS`
(антифлуд `ANSWER_COOLDOWN = 15` секунд).

## Что не задаётся кодом

Эти параметры живут в настройках Bot-Control, а не в конфиге:

| Параметр | Где задать | В конфиге |
|---|---|---|
| Токен бота | Настройки импорта | `BOT_TOKEN = "НЕ_ИМПОРТИРУЕТСЯ"` |
| Тумблер «Уточняющие вопросы» | Поведение и паузы | `CLARIFY_QUESTIONS` (3 фразы) |
| Запасной ответ | Поведение и паузы | не задан — бот молчит после кулдауна |
| ИИ на устройстве | Карточка бота | не используется, все ответы на правилах |
| Расписание / канал | Настройки бота | не заданы, режим «Объявления» выключен |

## Если замечания всё же появились

Импортёр обновляется, и правила могут меняться. Быстрая диагностика:

1. **«обработчик нажатия не найден», в тексте `callback_data` с `+`** —
   где-то осталась конкатенация. Нужен литерал.
2. **«меню объявлено, но не прикреплено»** — проверьте, что у функции нет
   аргументов и что она встречается как `reply_markup=имя()` в какой-нибудь команде.
3. **«текст ответа вычисляется в коде»** — в `send_message` попал не литерал:
   переменная, конкатенация, `.format()` или `join`.
4. **«нажатия не найден» при наличии обработчика** — обработчик использует
   `startswith`, `in` или разбор строки. Нужно точное `call.data == "значение"`.

Проверить локально можно скриптом из этого документа:

```bash
python3 - <<'PY'
import re
src = open('bot/imitation_bot.txt').read()

kb   = re.findall(r'KeyboardButton\("([^"]+)"\)', src)
cbs  = re.findall(r'callback_data="([^"]+)"', src)
hand = re.findall(r'call\.data == "([^"]+)"', src)
text = re.findall(r'm\.text == "([^"]+)"', src)

print("reply-кнопок:", len(kb), "| правил:", len(text))
print("callback_data:", len(cbs), "| обработчиков:", len(hand))

for b in kb:
    if b not in text: print("❌ кнопка без правила:", b)
for c in cbs:
    if c not in hand: print("❌ callback без обработчика:", c)
for h in hand:
    if h not in cbs: print("⚠️ обработчик без кнопки:", h)
if re.search(r'call\.data\.startswith', src): print("❌ есть startswith")
if re.search(r'^\s*(import|from)\s+\w', src, re.M): print("❌ есть import")
if "parse_mode" in src: print("❌ есть parse_mode")
print("готово")
PY
```
